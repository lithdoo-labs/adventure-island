# 逐函数阅读战役 — 第七批成果

## P1: 游戏主循环 — 物理Tick 的调用者链

物理 tick (0x5be703) 的直接调用者：
- 0x5d06d4（无上游调用者）
- 0x5c6028（无上游调用者）
- 0x5c2966（无上游调用者）

三者都没有静态上游 → **它们是虚表方法**（从帧循环虚表分派）。
这与 DLL 的 PCOM 虚表驱动一致——游戏主循环经 COM 接口调用。

**结论**：主循环不在反编译语料中可达（从物理 tick 逆推 3 层全断）。
主循环在 ASPLnchr/外部驱动器或经虚表间接调用。

## P3: 伤害数字显示链

FUN_004369cf（数字渲染）被 7 个函数调用：
- 0x55c5b2（攻击分派器 A）→ 攻击时显示伤害数字
- 0x55fe76（攻击分派器 B）→ 同上
- 0x58eae3 / 0x58fddf → 两个攻击后续函数
- 0x3ad267 → 命中处理
- 0x3aa8c0 / 0x297a2d → 辅助

**0x2aa857（115KB）含 'fixedDamage' 字符串** → 伤害计算/显示巨函数！

## 伤害数字渲染链完整

```
攻击命中 → FUN_004369cf(range=500, base=[ebp-0xbb0], target, ...)
         → 数字字体系统 (DAT_00be7330)
         → 屏幕坐标渲染
```

fixedDamage 函数（0x2aa857, 115KB）是伤害计算+显示的核心。
