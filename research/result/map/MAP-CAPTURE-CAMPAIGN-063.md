### 修复的编排缺陷（复用时必读）
1. **mcopy 参数顺序**：源在前目标在后；`-s` 对文件是错的；**写后必须回读校验**
2. **QEMU monitor readline 吞行**：socat 需保持 stdin 打开（`{ printf; sleep 4; }` 模式）
3. **loadvm 被 raw 盘阻塞**：必须先 usb-detach 再 loadvm 再 cont 再 usb-attach
4. **VM status "prelaunch"**：loadvm 后必须显式 `cont` 并验证 "running"
5. **typefile 字符表**：`|`、`?`、`~` 不在映射表（静默丢失）；引号易损；长命令损坏率高（曾把 for 打成 f0r）
6. **guest 时钟每次 loadvm 重置**：阶段标记文件必须每会话清零，否则跨会话混读
7. **alt-f4 对桌面 = 关机对话框**（曾误触发关机）——只用 esc
8. **UAC 定时**：alt-y 必须在 RunAs 真正弹出后（等 elevate-requested 标记），过早必失败
9. **Ctrl+Shift+Enter 开始菜单搜索**= 一次性提权 cmd 的可靠路径（之后 RunAs 免 UAC）
10. **观察器点击语义**：必须按文字匹配（036 原版"运行此程序"/iloveaki 标题），"第一个按钮"策略会点错

## 一级证据发现（细化保护壳模型）

### F1: NIC 在场 → 游戏冻结在 1.5MB（保护壳 NIC 检查 = 挂起而非退出）
提权 + 网卡在场启动：进程存活、内存 1.5MB 恒定、无窗口。
**细化 task-053**：NIC 检测的行为是无限挂起（不是立即退出）。

### F2: 无 NIC → 游戏自旋锁死在 4.9MB（模态之前）
三次独立会话（参数 10.0.2.2 / 127.0.0.1、提权/非提权、含/不含容器重启）：
- 进程存活，内存 4,916-4,920K 恒定（10 分钟 <5KB 漂移）
- QEMU CPU 持续 140-152%（满核自旋）
- 安全对话框（"运行(&R)"）被正确点击后进入此状态
- iloveaki 模态永不出现

**对照**：task-036 同快照同参数同无网环境，游戏 90 秒到模态、WS 7.9→16.4MB、
300 秒采样成功。**当前会话与 036 之间的环境差异未定位**——这是诚实的未解项。

### F3: 启动参数不影响 F2
127.0.0.1（立即拒连）与 10.0.2.2（无路由超时）行为相同——排除"登录地址探测挂起"假说。

### F4: client.img 原始性（哈希验证）
F:\MapleStory.exe = 5D280CF1...4D、F:\iloveaki.dat = 41D37BFB...A1，
与原始客户端 RAR 逐字节一致。**排除"客户端被后续任务修改"假说**。

### F5: snapshot=on 覆盖层致盲（基础设施级发现）
`drive_add ... snapshot=on` 的盘：guest 写入进入临时覆盖层，宿主 mtype 读基础
镜像**永远看不到**——曾造成多轮"零标记"假阴性。直写挂载（无 snapshot）才能
让 guest 写入对宿主可见。

### F6: Win7 引导期 USB 枚举失败
全新引导（fresh boot）时预挂的 QEMU USB MSD 不被 Windows 枚举（G: 不存在，
"系统找不到路径"）。**热插（登录后在运行中的系统上挂载）每次成功**——这是
旧流程（loadvm 恢复 + 热插）盘可用的真实原因。

### F7: 自动播放风暴的根治
USB 盘在**快照恢复（loadvm）前**以 snapshot=on 预挂 → Windows 恢复会话时盘
已在位 → **不触发自动播放**（2/2 验证）。此法仅适用于 loadvm 流程；全新引导
受 F6 制约需改用登录后热插（会触发弹窗，需 esc/ret 清场）。

### F8: Win7 登录屏键盘配方（实证）
点击用户磁贴 → 点击密码框 → 输入 research → 点击箭头 → **双回车**。
（单纯 Enter→输入→Enter 不可靠：焦点时序问题。）

1. **盘毒化假说：彻底否定**。全量 141 文件哈希对比（特权容器挂载 client.img
   只读 vs 仓库 pristine 副本）：**零修改**。多出的 6 个文件（回收站/system 标记/

4. 容器升级为 --privileged（losetup/NTFS 挂载能力常驻）。
5. 全新 QEMU 会话（容器重建后首启）+ pristine 盘 + 提权链：启动打字在最后一步
   再次失败（cmd 焦点漂移），游戏本轮未启动；F2 未获再次验证机会。

下次尝试的优先假说（按可能性排序）：

1. **观察器枚举干扰**：我的观察器从游戏启动起以 0.4s 间隔 EnumWindows/
   GetWindowText（提权进程）——保护壳可能将高频窗口枚举判为外挂行为并自旋。
   036 的观察器节奏不同。对策：轮询间隔 ≥2s，或游戏启动后暂停枚举只等模态。
2. QEMU 会话新鲜度（本次未能完整验证——启动链断在打字）
3. 桌面窗口/对话框堆积状态

编排可靠性的最终教训：即便"验证过的组合"也会因会话焦点漂移而失败。
若继续，把 T063GO 挂进 guest 启动项（startup 文件夹，一次性提权写入），
彻底消灭启动打字环节（task-043 当年已指出，本轮验证了其分量）。
