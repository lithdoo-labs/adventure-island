# 攻击、跳跃、下跳、坐下、爬绳

地址是解包映像 VA。静态反汇编，没有运行时断点。`Physics.img` 的字段名（`walkForce`、`jumpSpeed`、`gravityAcc`、`swimForce`、`flyJumpDec`）不在这张映像的字符串池里。下面不把那些数写成已经对上的客户端公式。

North、South、East 是产品手柄面键，不是这张映像里的虚拟键。客户端方向键用 `0x25`–`0x28`。

## 按键入口

`0x9533EA` 读两个参数。第一个是虚拟键。第二个的高 16 位再取低 8 位，是动作号。第二个参数的最高字节带 `0x80` 时走松开。

虚拟键为 `0x25`、`0x26`、`0x27`、`0x28` 时，如果虚表 `+8` 所返回对象上 `+0x7D4` 那条字符串非空，左右对调，上下对调。按下路径里：

| 虚拟键 | 按下后 |
|---|---|
| `0x26` 上 | 只调用 `0x954B58` |
| `0x25` 左、`0x27` 右 | 调用 `0x6A0ADF`。返回 0 就结束。返回非 0 时调用 `0xA18753(field, 0xC8)`。这里没有行走 |
| 其他，包括 `0x28` 下 | 调用 `0x955C96`，再调用 `0x969DEB` |

`0x955C96` 按动作号分支。和这次目标有关的是：

| 动作号 | 函数 | 等级 |
|---|---|---|
| `0x33` | `0x95516A` | VERIFIED 进入座位搜索。没有看到它写入 `sit` 动作名 |
| `0x34` | `0x954F0F` | VERIFIED 经过一串门之后调用 `0x9573A6` / `0x95C5B2`。挥砍范围和动作名未还原 |
| `0x35` | `0x95308C` 或 `0x952F1F` | VERIFIED 分裂。`0x5CAAA9(0x28)` 非 0 走下跳，否则走 `0x952F1F(0)` |

默认键位表没有还原。产品决定不再追这张表，按键用设计草案第 6.3 节。因此不能把动作号 `0x33`、`0x34`、`0x35` 写成某个虚拟键的默认绑定。`0x9533EA` 的一个调用点 `0x9514BD` 先经 `0x9529C0` 从队列取出两个 dword，再把它们当参数传进来。`0x9529C0` 只复制队列项，不是键位表。`0x952F1F` 的函数体里没有 `prone` 这个字符串。

另一处轮询 `0x953A4F` 先看上，再看左，再看右。按住上时算出一个大整数并调用 `0x974307`，不进入 `0x954B58`。

## 上键：传送，然后才是另一张表

`0x954B58` 的前置失败就返回：`0x451B00(this+0x88) > -1`，`0x96C96B` 非 0，`0x952A38` 非 0，或者移动对象 `+0x110` 为 0。`+0x110` 在下跳函数里同样被当作当前立足对象，为 0 时两条路径都退出。

通过之后用人物位置调用 `0x71B44D(portalManager, x, y, 0x14)`。`portalManager` 是全局 `[0xBDEB48]`。

`0x71B44D` 走 `[this+4]`，不是 `0x71B4FD` 用的 `[this+8]`。`[object+8] == 0` 的项跳过。矩形四边按压栈顺序是 `x-20`、`y-50`、`x+20`、`y+50`，然后用和 `hRange` 测试相同的两个调用槽做点测试。这是固定框，不读 `hRange` / `vRange`。

命中且 `[portal+0x1C] != 999999999`：

- 当前地图 id 等于 `tm`，并且 `pt` 不是 4 也不是 5：`0x963C7D(this, 0, 0, pn, tn, 0)`。返回非 0 才播放字符串 `Portal`。
- 当前地图 id 不等于 `tm`：`0x53FF69(field, -1, pn, 0)`。`pt` 为 4 或 5 时不再播放 `Portal`。

`tm == 999999999` 时，只有 `pt` 为 7、8、11 才继续，那条是 `0x495C5C`，不是这次的四扇门。没有命中，或者哨兵 `tm` 的 `pt` 不是这三档，才落到 `0x954E90`。

`0x954E90` 先调用 `0x5CDE3F(x, y)`，非 0 就返回。然后看 `field+0x14C`。地图加载把 `town` 的取值结果存在这里（`0x534C60`）。`town == 0` 调用 `0x7C41E5`。`town != 0` 调用 `0x54744E`。

`0x54744E` 走的是 `field+0x170`，框是点的 `x±20`、`y±50`，命中后可能发 `0x495C5C`。这不是下面的 `seat` 数组。`0x7C41E5` 走对象 `+0x28` 的链表，框同样是 `x±20`、`y±50`，命中也发 `0x495C5C`。两条都没有写入 `ladder` 或 `sit`。

三张验证图里，村和井的 `town` 是 1，上键错过传送门之后走 `+0x170`。矩形地带的 `town` 是 0，走 `0x7C41E5`。

## 坐下

地图加载 `0x5364B8` 读取字符串 `seat`，把记录放进 `field+0x16C`。每条 8 字节，两个整数。点测试把第一个当 x，第二个当 y。

动作号 `0x33` 的 `0x95516A` 在 `0x6A0ADF` 返回 0 时继续。`0x9552BD` 要求 `+0x110` 非 0，并且 `0x93D2E2` 返回 1。`0x93D2E2` 把两段双精度都和 `0.0`（`0xAFECC0`）比较，两段都相等才返回 1。然后 `0x54634C(field, x, y)` 在人物周围做矩形：左右各 10，上下各 30。座位的点落在这个矩形里就返回下标，否则 `-1`。下标 `>= 0` 时把下标交给 `0x495C5C`，并写 `field+0x2088 = 1`。

这条函数没有出现 `sit` 字符串。坐下的画面动作是否在发报文之前本地写上，UNKNOWN。

`Map.wz` 里 `222000000.img`、`222000001.img`、`230030200.img` 的顶层都没有 `seat`。转换库因此没有这三张图的座位文件。不是导入时漏写。

## 下跳

`0x95308C` 是下跳。调用点是 `0x953779` 和 `0x955F47`，都在动作号 `0x35` 的路径上。

按顺序，任一条件成立就返回：

1. `0x5024C5` 返回 0，并且 `field+0x13C` 的 bit 17 为 1。这个位的名字没有在这条函数里出现。`forbidFallDown` 是立足线加载时的另一个字段，不能写成就是这一位。
2. `0x96C96B` 非 0。
3. `0x95306D` 非 0。它看虚表 `+8` 所返回对象的 `+0x4C4` 字符串是否非空。
4. `0x952A38` 非 0。它看同一对象的 `+0x32C` 字符串是否非空。
5. `0x71B4FD` 命中的 portal，其 `pt` 是 12 或 13。其他 `pt` 不在这里拦住。
6. `0x451B00(this+0x88) > -1`。
7. `[user+0x2928] != 0`。
8. 移动对象 `+0x110` 为 0。
9. 对当前立足对象调用 `0x96E48B` 的结果非 0。

通过之后把人物 y 加上 `0x12C`（300），调用 `0xA4F609(x, y+300, out, 0x80000000)`。结果为空或等于当前立足对象时，再调用 `0xA4F6F1`。这次压栈从右到左是 `1`、`y+600`、输出指针、`y+300`、`x`，`ecx` 来自 `[0xBDD498]`。也就是 x 方向半宽 1，竖直范围从 `y+300` 到 `y+600`。

`0xA4F6F1` 的 `ret 0x14`。它在这个范围内找立足段，把插值得到的 y 写进输出指针，返回值是那段立足对象。它不写人物坐标。成功条件看的是这个输出 y 和人物当前 y：输出落在 `(y-5, y+5)` 里面则不置成功。输出在这 10 像素开区间之外，并且返回的立足指针非 0，才把 `[user+0x2928]` 写成 1，把当前立足对象记到 `[user+0x292C]`，调用 `0x940011(this, 1, 1)`。两个参数都是寄存器里的 1。

`0x940011` 只做效果。它读 `Effect/SetEff.img/%d/backgrnd`，不调用 `0x6131F4`，也不写 `+0x50`/`+0x68`。`0x95329D` 返回之后，`0x95308C` 只释放局部对象。速度不在这个函数里。

下跳在调用 `0x940011` 之前已经把 `[user+0x2928]` 写成 1，把当前立足对象记到 `[user+0x292C]`。用户更新 `0x951470` 调用 `0x95539D`。`+0x2928` 非 0 时清掉它，把移动对象 `+0x160` 写成 1，把保存的立足对象写到 `+0x164`，再调用 `0x53E95D(move, 0xE)`。物理分发 `0x9BCD6C` 在 `+0x160` 非 0 时调用 `0x9BCFED`。`0x9BCFED` 先把 `+0x160` 清 0，再写速度。

`0x6131F4` 不是校验包装。`ecx` 指向 16 字节的一块。栈上的双精度拆成两个 dword，循环两次，写入 `[ecx+0]` 到 `[ecx+0xC]`。`eax` 带回累加结果。调用方把 `eax` 存到这块之后 `0x10` 的 dword。坐下判定 `0x93D2E2` 用 `0x548806` 把 `+0x50` 配 `+0x60`、`+0x68` 配 `+0x78` 还原成两段双精度，再和 `0.0` 比较。所以写 `+0x50` 的调用把校验放在 `+0x60`，写 `+0x68` 的调用把校验放在 `+0x78`。

下跳的竖直速度是 `decrypt([move+0x190]+0x24) / ([[[0xBDD498]+8]+0x70] * K)`。`K` 在 `0xB0C590`，值是 `-0.35355339`。水平速度写成 `0.0`。竖直进 `0x6131F4`，目标是 `+0x68`，校验到 `+0x78`。水平目标是 `+0x50`，校验到 `+0x60`。`decrypt` 是 `0x6A0545`。`[move+0x190]+0x24` 和全局 `+0x70` 的 WZ 字段名 UNKNOWN。

`Effect/BasicEff.img/VerticalJump` 不在 `0x95308C` 里。那个名字在 `pt` 13 的使用路径，以及 `pt` 12 调用的 `0x9549DF`。`0x9549DF` 还读左右键，水平偏移按朝向取 200 再加减 100，并加载双精度常量 `-2300`（`0xB0BD88`）。这是传送门类型 12 的效果，不是人物的下跳函数。

动作号 `0x35` 的另一支 `0x952F1F` 在参数为 0 时，会把移动对象 `+0x158` 写成 1。函数体里仍然没有 `prone`。不能把这次写入当成已经证明的蹲下。

## 陆地跳和水中跳

`info.swim` 在 `0x534C86` 用字符串号 `0xBEF` 读出，`0x534CBE` 收成 0 或 1，存在地图对象 `[esi+0x150]`。`0x95A31E` 不读这个地图对象。它前面是 `call 0x4376F2`，再读返回值的 `+0x150`。`0x4376F2` 返回全局 `[0xBDF54C]`。这一读还要 `0x697863` 先返回 2；全局 `+0x150` 为 0 时才把局部 `[ebp-0xD68]` 写成 10，然后跳到 `0x95A7D0`。10 没有对上动作表下标。这不是起跳公式。

`0x9BD238`、`0x9BD905`、`0x9BD9D7` 读的是另一对象的 `+0x150`。非 0 时把它转成双精度，乘上栈上的另一值，再和 `0.0` 比符号。小于等于 0 的一支再乘 `-0.8`（`0xB0C598`）。没有证据表明这个 `+0x150` 就是地图的 `swim`。

身体动作名表在 `0x4A87FD` 附近有 `fly`、`jump`、`ladder`、`rope`、`sit`、`prone`。`0x4A887B` 和 `0x4A88BA` 把 `ladder`、`rope` 注册进这张表，没有比较 `l`。字符串池里没有名为 `swim` 的身体动作。哪一个动作号在 `swim == 1` 时播放，UNKNOWN。

`0x9BCFF2` 先用 `0x4B6ABE` 校验 `+0x124`。返回非 0 时走虚表 `+0x14`，不读 `Jump`。返回 0、立足对象 `+0x110` 非空、并且 `[esi+0x14]` 的虚表调用返回 0 时，才读取字符串 `Jump`（2047）。函数入口是 `0x9BCFED`。读完名字之后，`0x9BD088` 仍把竖直速度写入 `+0x68`/`+0x78`，水平写成 0。

`0x9BD0DE` 在对象 `+0x150` 非 0 时有两步。第一步把 `0x6A0545` 解出的双精度除掉另一值，乘上 `0.3` 或 `0.5`（`0xB05538`、`0xAFEC20`），再取负，交给 `0x6131F4`。第二步把另一处解出的双精度乘上这个 `+0x150` 的整数，再乘 `1.3`（`0xB064B0`），同样交给 `0x6131F4`。`0.7`（`0xB06458`）和 `0.8`（`0xAFEC18`）在 `0x9BD1BB`，那条先看立足对象 `+0x110`，不是上面这一支。这些常数不是 `jumpSpeed`，也不是 `gravityAcc`。

没有找到把 `field+0x150` 抄进移动对象 `+0x150` 的指令。`0x952A57` 按 dword 复制整个同类对象，源是参数，不是地图 `field`。`0x9C4B78` 只把两个参数写进 `+0x150` 和 `+0x154`，它还有别的调用点。爬绳函数在 `0x9D7B8B` 读左右上下键，`0x9D7BF2` 把水平的 -1/0/1 和竖直的 -1/0/1 传进去。因此 `0x9BD0DE` 读到的 `+0x150` 仍不能当成 `info.swim`，也不能叫水中跳。

陆地跳走另一条。动作号 `0x35` 未按住下时，`0x952F1F` 把移动对象 `+0x158` 写成 1。`0x9BCD6C` 看到 `+0x158` 就调用 `0x9BD567`，清掉 `+0x158`，再调用 `0x9BD0D9`。`0x4B6ABE` 返回 0 并且 `+0x110` 非 0 时，`0x9BD20E` 写竖直速度：

`-(decrypt([move+0x198]+0x48) * [[[0xBDD498]+8]+0x70]) / decrypt([move+0x190]+0x24)`

目标是 `+0x68`，校验到 `+0x78`。`0x9BD455` 返回非 0 时，把刚写入的值再乘 `0.7` 写回去。`+0x150` 为 0 时这条不写水平速度。`+0x110` 为 0 时进入 `0x9BD367`。入口 `cmp ebx, edi`，相等就跳到 `0x9BD444`，eax 写成 0，不写速度。不相等时先 `decrypt([move+0x190]+0x18)`，再交给 `0xA70FBB`。`0xA70FE1` 在指数不是 `0x7FF0` 时跳到 `0xA7104F`，那里清掉高位 dword 的符号位后再送回。然后才调用 `0x70DF65`。返回非 0 时取 `decrypt([move+0x198]+0x6C)`，乘 `[[[0xBDD498]+8]+0x48]`，再乘刚才送回的双精度，再乘 `0xB04F40` 的 `5.0`，跳到 `0x9BD42D`。返回 0 且虚表 `+8` 非 0 时，改乘全局 `+0x90` 和 `+0x58`，同样乘那份双精度和 `5.0`；`+0x150` 为 0 时也进 `0x9BD42D`。`0x9BD42D` 做 `fchs`，`0x6131F4` 写入 `+0x68`，校验放在 `+0x78`。

`0x9BC2EB` 在 `0x9BC378` 和 `0x9BC37E` 把 `[this+0x190]`、`[this+0x198]` 写成 0。派生构造 `0x9D78C2` 只写入虚表 `0xB0CC78`，不给这两个槽放对象。`+0x48`、`+0x6C`、`+0x24`、`+0x18` 旁边没有紧跟 `call 0x7A48D0` 的字段名。`0x70D253` 到 `0x70D399` 按这些偏移把已经加密的双精度抄到另一个对象的 `+0x12C`，仍然没有字符串。字段名 UNKNOWN。`0x692940` 那一族仍是写到别的对象，旁边也没有字段名。

`0x95A31E` 和 `0x69733B` 读的都是 `0x4376F2` 返回的全局 `[0xBDF54C]+0x150`。`0x69733B` 所在函数从 `0x697240` 起，`ebx` 先被写成 1；那个 dword 为 0 时局部 `[ebp-0x18]` 写成 1，非 0 则清 0。`0x69744B` 把这个局部传给 `0x699C57`。全局指针本身，`0x77E64E` 把它和成 0，`0x77FB40` 在 `ebx` 已经是 0 时再写一次 0。`0x690000` 到 `0xA10000` 里没有别的寄存器写入。地图加载写的 `[field+0x150]` 和这个全局还没有对上。水中跳仍 UNKNOWN。身体动作名表里也没有 `swim`。

`0x9BD58F` 是后来的速度修正，不是行走、游泳或重力的逐步积分。它把移动对象上的普通双精度 `+0x180`、`+0x188` 取出。`+0x180` 小于 0，并且当前水平速度大于它时，把这份值加到 `+0x50` 再经 `0x6131F4` 写回，校验放在 `+0x60`（`0x9BD662`）。`+0x188` 走同一比较，`0x9BD6A2` 把它加到解密后的 `+0x68`，`0x9BD6F0` 经 `0x6131F4` 写回，校验放在 `+0x78`。这两处普通双精度在 `0x690000` 到 `0xA10000` 没有对应的 `fstp` 写入。`0x691976`、`0x69A8A7`、`0x6C5417` 写的是 dword 的 `+0x188`，对不上这里的 qword。字段名 UNKNOWN。

## 绳子

地图加载 `0x66622E` 读取 `ladderRope`，随后 `0xA4DDDB` 解析。单条记录：

| 偏移 | 字段 | 存储 |
|---|---|---|
| `+4` | `l` | 非 0 收成 1 |
| `+8` | `uf` | 非 0 收成 1 |
| `+0xC` | `x` | 原整数 |
| `+0x10` | `y1` | 原整数 |
| `+0x14` | `y2` | 原整数 |
| `+0x18` | `page` | 原整数 |

地图加载把解析结果交给 `0x4B6A47`，再调用 `0xA4DDDB`。`0x4B6ABE` 是带 `0xBAADF00D` 的指针校验，解开后返回指针，不是爬绳查询。

`0xA4DDDB` 把绳子写进 `this+0xA8` 的数组，没有字段写完后再插入的另一次调用。`0xA4EFDA` 把子节点数加 1，交给 `0xA51577`。有效记录从偏移 `0x1C` 起，步长 `0x1C`。运行时查询的 `ecx` 是 `[0xBDD498]`。

查询函数是 `0xA4FC6F`。它把两个 x 参数排成低到高，低的减 10，高的加 10。两个 y 参数只排序。从下标 1 遍历。命中要同时满足：x 低界 `<=` 记录 `+0xC` `<=` x 高界，y 低界 `<=` 记录 `+0x14`，记录 `+0x10` `<=` y 高界。命中返回记录指针，否则 0。

`0x9D7ADA` 是移动对象上的方法，函数指针在 `0xB0CCA0`，没有直接 `call`。人物 x 在 `+0x20`，y 在 `+0x38`，都是 `0x6131F4` 那种成对双精度。`0x9D7E9F` 先按符号加减 `0.5` 再转成整数：非负加 `0xAFEC20`，为负则减 `0xB00D60`。x 同时当作两个 x 端点，y 端点是这个整数和它减 20。查询再把 x 向两边扩 10，所以这一次是 x 各 10、竖直 20。`0x9D7D4F` 用 `+0x20` 和 `+0x80` 做 x 的两端，`+0x38` 和 `+0x98` 做 y 的两端。`0x9D7CE1` 是 `lea edi, [ebx+0x80]`，`0x9D7CEA` 再加 `0x18` 去读 `+0x98`，校验在 `+0xA8`。`0x9C9DF6` 另有一次 `lea eax, [esi+0x80]`，校验用 `[esi+0x90]`，没有把这里的 esi 系到这个移动对象。`0x6131F4` 的调用点前 48 字节里没有位移 `0x80` 或 `0x98`。写来源没看到，这两个字段仍没有名字。还有一处 `0x9D8015` 在调用前给一个坐标加 10。

`0x9D7D5A` 命中后把 `+0x68`/`+0x78` 和 `+0x50`/`+0x60` 写成 0，把 `+0x20` 写成记录 `+0xC`，然后 `call [vtable+0x14]`，参数是 0、记录指针、0。这里不比较 `+4`，也不读 882 或 884。

已经解开 `+0x124` 且非 0 时，`0x9D7C11` 调用 `0x9D80EC`。它把 y（`+0x38`）加上 `3`（`0xB00D68`）乘 `+0x154`。`+0x154` 是 `0x9D7BF2` 传进 `0x9C4B78` 的竖直键，上为 -1，下为 1。`+0x154` 小于 0 并且 y 小于记录 `+0x10` 时，记录 `+8` 非 0 就把 y 写成 `+0x10` 减 5，为 0 则改写另一处解开指针的 `+0x10`。`+0x154` 大于 0 并且 y 大于记录 `+0x14` 时，写成 `+0x14` 加 1。

`0x9D7ADA` 开头 `mov ebx, ecx`。这个函数只出现在 `0xB0CCA0`，而 `0x9D78C2` 把虚表 `0xB0CC78` 写进对象。`0xB0CCA0` 是这张表的 `+0x28`，所以 `0x9D80DF` 的 `call [eax+0x14]` 进入 `0xB0CC8C` 上的 `0x9BFB52`。

`0x9BFB52` 不比较记录 `+4`，也不读 882 或 884。这次参数是 0、记录、0。它读记录 `+0x18`。页和 `+0x130` 不同，或者 `+0x134` 非 0 时，把页写进 `+0x130`，并把 `+0x134` 写成 0。这条上还把 `+0x118`、`+0x16C`、`+0x110` 写成 0。`0x9BFD85` 用 `0xBAADF00D` 那套守卫把记录指针放进 `+0x124`，守卫字放进 `+0x128`。调用方把返回值存进 `+0x12C`。守卫字不是记录的 `l`。随后 `0x9BFC35` 调用 `0x6B8949`。立足参数已经是 0，所以 `0x6B8949` 读记录开头的一个字并取负，不是 `+4`。

另一张虚表 `0xB0CB70` 的 `+0x14` 是 `0x9D3CCA`。末尾 `0x9D3DDA` 把三个参数原样转给 `0x9BFB52`。函数里的 `+4` 来自 `this+0x14` 所指对象减 4，不是绳子记录的 `l`。`0x9D47FA` 调用的是同一槽。`0xA4FC6F` 体内没有位移 4。字符串 882、884 紧跟 `call 0x7A48D0` 的 push 只有 `0x4A8881`、`0x4A88C0`、`0x4AA74E`、`0x4AA78A`。爬绳这条路径不在其中。记录 `+4` 的下一个读者没有落在这些地址上。`l` 选 `ladder` 还是 `rope`，UNKNOWN。

动作名表 `0x4A7F89` 仍用 `0x7A48D0`、`0x406368`、`0x4AEE0B`、`0x4AA4AE` 登记。`mov [ebp-4], 0x24`（`0x4A889D`）和 `mov [ebp-4], 0x25`（`0x4A88DC`）是 SEH 状态：`0x4A7FCB` 把 edi 设成 -1，每条登记完都把 `[ebp-4]` 设回 edi。传给 `0x4AEE0B` 的两个数都是 esi，esi 只在 `0x4A7FB1` 被清成 0，记录里不带槽号。运行时用下标乘 `0x18` 再加 `0xBDDB10`，见 `0x958FDC`、`0x95D8CA`、`0x4118F9`、`0x977186`。`ladder` 写在 `0xBDDE70`，距基址 `0x360`，下标是 `0x24`。`rope` 写在 `0xBDDE88`，下标是 `0x25`。名字是整个字符串号 882、884，不是拼出来的。这次仍然没有把这两个下标写到人物上。`0x4AA74E` 和 `0x4AA78A` 把同一对名字放进另一组全局 `0xBDDA78`、`0xBDDA7C`，旁边的 `[ebp-4]` 是 9 和 `0xA`，同样是 SEH 状态。`uf` 和 `page` 仍不解释。矩形地带的 `ladderRope` 节点存在，子节点数是 0。

## 攻击

`0x99772D` 在参数等于 `0x27` 时读取 `Attack`，等于 `0x28` 时读取 `Attack2`，再格式化 `Sound/Weapon.img/%s/%s`，交给 `0x442F50`。这是武器音效，不是身体动作，也不是命中。`0x938547` 传入 `0x27`。`0x43FCA7` 传入 `0x28`。两个调用点都不在 `0x954F0F` 里。

动作名表里，`swingO1`（853）和 `stabO1`（864）登记时压的是整个字符串号，没有拼接。`[ebp-4]` 上的 5 和 `0x10` 是 SEH 状态，不是写进记录的槽号，依据和上面 `ladder` 的 `0x24` 相同。记录按 `0x18` 从 `0xBDDB10` 排开。`swingO1` 第一条在 `0xBDDB88`，下标是 5。`stabO1` 第一条在 `0xBDDC90`，下标是 `0x10`。后面重复的 `swingO1` 在下标 `0x18`、`0x1C`，`stabO1` 在 `0x1E`。

动作号 `0x34` 进入 `0x954F0F`。`ebx` 在 `0x954F1E` 清 0。到第一次 `call 0x9573A6`（`0x955126`）为止，没有把 5 或 `0x10` 写到人物上。`0x955139` 在这之后调用 `0x95C5B2`，`0x95C5B2` 自己就是 cookie 起点。它把一个下标放在局部 `[ebp-0xC68]`：`[ebp-0xD58]` 非 0 时写成 `0x4E`（`0x95CACA`），`[ebp-0xD54]` 非 0 时写成 `0x57`（`0x95CAE2`），`[ebp-0xD20]` 非 0 时写成 `0x61`（`0x95CAFA`）。这三支都不是 5 或 `0x10`。`0x95CB70` 还有一支把这个局部或成 -1。`0x95CB94` 调用 `0x773491`，那个函数里没有立即数 5 或 `0x10`，返回 -1，或者 `0xBA59BC` 上的表项。`0x95D8C7` 用这个下标乘 `0x18` 加 `0xBDDB10`。`swing` / `stab` 的选择 UNKNOWN。

`0x9573A6` 内部没有调用 `0x495C5C`。`0x95D4A2` 调用 `0xA4F93C`。两个整数来自 `[user+4]` 虚表 `+0x10` 所返回指针的 `[+0]`，以及 `[+4]` 减 `0x1C`（`0x95CFF9`）。没有对上人物 `+0x20`、`+0x38`。`0xA4F93C` 自己就是 cookie 起点。它用两个指针的首 dword 减去两个参数。差都是 0 时在 `0xA4F970` 直接返回 1。否则把这两对坐标交给 `0x5114AA`。`0x5114AA` 也是 cookie 起点，只把每对坐标排成低、高，再把这块矩形传下去，函数体里没有固定半宽。`[ebp-0xBEC]` 等于 `0xE6935E` 时改读 `[user+0x2984]`、`[user+0x2988]`，那是技能编号分支，不当普攻。命中范围仍 UNKNOWN。再读这两个函数得不到半宽。

低层键盘轮询 `0xA7E7C3` 会读虚拟键 `0x11`。那段没有调用 `0x954F0F`。

`0x954F0F` 到 `0x95D000` 之间没有读到 `Attack`、`Attack2`、`swingO1`、`stabO1`。`0x95BDE8` 处等于 1472 的四字节是一条 `call` 的相对位移，不是 `jumpAttack`。这段里按技能编号分支，调用 `0x95C3AC`，不是这次要的普攻命中框。
