# 终极阅读分析（60 函数信号提取 + 深源审视）

## 渲染引擎关键发现

### Gr2D_DX8 top-20 模式
- 最大函数（35KB/34KB）各只有 1 个调用者 → 初始化/主循环级
- 0x5000418c（13KB，98 调用）引用 'Canvas' → 渲染-画布桥接
- 0x500030d3（9KB）有 'Already_initialized' → 初始化守卫
- **几乎无 gfx API 直接调用** → D3D 调用走 vtable/COM（虚表间接）
- 全部 DLL 大函数都是纯虚表驱动 → **渲染管线需要虚表解析才能标注**

### Canvas top-10 模式
- 0x4fc1ef78（8KB）有 'origin' + 'Property' → **WZ 属性-画布桥接函数**！
- 其余大函数无字符串锚 → PCOM 内部方法

## UI 巨函数信号（179KB 级）
- **零加密读写**（encR=0, encW=0-2）→ UI 层完全不使用加密存储
- 虚表调用密集（16-30 个）→ UI 事件分派走虚表
- 多模块标签继承 → UI 函数跨模块复用
- 字符串锚稀少 → 布局/逻辑在代码中硬编码

## 移动物理补充
- 0x5bcfed（1KB，phys=1）：小型物理辅助
- 0x5bd492（1KB，encR=6, phys=2）：密集解密+物理 → 速度查询器
- 其余 0KB = 空壳或已内联
