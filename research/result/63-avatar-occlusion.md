# 63 — 纸娃娃遮挡函数

日期：2026-11-07。样本是 Task 036 从本机离线虚拟机内存里抽出的游戏映像，文件在 `.work/task-036/game-image-unpacked.bin`，不进入 Git。映像基址 `0x400000`，文件偏移等于 RVA。只做静态反汇编，没有改客户端，没有在客户机里下断。

`components/cms-actor/DESIGN.md` 和 `content/adventure_design.md` §2.5 里的四条遮挡规则是按 `smap` 和样本 `vslot` 对出来的读法。这次把执行这张表的函数还原出来了。下面凡是写「已还原」的，都能在给出的地址上对上指令；写「未闭合」的，这次没有追完。

## 结论

一张画布画不画，由同一帧里谁占住了它的槽位决定。zmap 给每个层名和一个两字符槽名各一个整数，用来排绘制先后，也用来比哪件装备优先。smap 只提供「这个 z 名覆盖哪些槽」。

装入一张画布时算出：

```text
priority = max(zmap[token] for token in islot)     # 画布 +0x18
tag      = vslot ∩ smap[z]                          # 画布 +0x14
zIndex   = zmap[z]                                   # 画布 +0x24
```

`tag` 和 `vslot`、`smap[z]` 都按两个宽字符一组切开。交的结果只保留 `vslot` 里确实出现在 `smap[z]` 中的槽，顺序跟 `vslot`。任一串的字符数是奇数，求交失败。

同一帧里再走一遍 `tag`。每个槽位只归 `priority` 更大的那张画布。输的那张整张不画，它剩下的槽位不再看。`priority` 相等时两张都留着。同一件装备的画布共用一个 `islot`，所以 `priority` 相同，自己不会挡住自己。动作对象 `+0x38` 上预先登记的槽位值是 0，不参加编号比较：任何 `tag` 含有这些槽位的画布整张不画，而且后来的画布抢不走这些键。

绘制时看包装对象 `+0x14`。这个标志先写成 1，冲突失败才写成 0。为 0 就跳过。z 序号等于 `zmap["face"]` 的画布根本不进入这一帧的链表。

部件数组的顺序不参与谁挡住谁。相等 `priority` 时，后装进链表的画布画在前面，那只影响叠放。

## 1. 样本和已经排除的路径

映像大小 `0x9DA000`，与 PE 的 `SizeOfImage` 一致。RTTI 只剩异常类，没有 `CAvatar`。明文里没有 `smap`、`zmap`、`vslot`、`islot`、`stand1`、`navel`。装备部位名 `hair`、`cap`、`weapon` 是明文，集中在文件 `0x7A1558`。

## 2. 字符串池

WZ 属性名在字符串池里。已还原的布局：

| 项 | 文件偏移 | 内容 |
|---|---|---|
| 主密钥 | `0x707640` | 16 字节 |
| 密钥长度 | `0x707650` | dword `16` |
| 条目数 | `0x707654` | dword `5566` |
| 指针表 | `0x7A7B04` | `5566` 个 VA |

每条的第一个字节是有符号种子，后面是以 `0` 结尾的密文。解码把 16 字节密钥按种子做循环左移，再逐字节异或。密文字节等于当前密钥字节时，明文保留密钥字节，避免密文里出现假的结尾 `0`。懒解码在 `0x7A4A5E`，异或循环在 `0x7A4DA9`：`xor [esi], al` 结果为 0 时把 `al` 写回去。取字符串的常见形状是 `push 编号; push 目标; call 0x7A48D0`。

密钥字节不写入本报告。这次用到的编号：

| 788 | `zmap.img` |
| 798 | `origin` |
| 800 | `info` |
| 819 | `z` |
| 920 | `brow` |

`info` / `islot` / `vslot` 在 `0x40A580` 附近连续读取。`islot` 写到物品 `+0x10`，`vslot` 写到物品 `+0x14`。已还原。

## 3. zmap 编号

`0x4011C6` 枚举 zmap 的子节点。子节点在文件里是空属性。变体类型为 0 时走赋值分支：计数从 0 开始，每遇到一个空属性就减 1，再把这个整数写回该属性。文件里第一个名字得到 `-1`，越靠后越小。已还原。

因此靠前的层数值更大。本地 `zmap.img` 的顺序是从 `mobEquipFront` 到 `characterEnd`，尾部才是两字符槽名，`Cp` 在 `Hr` 前面，`Hr` 在 `Hd` 前面，`Bd` 在最后。islot 能按两字符去查 zmap，是因为这些槽名本身就是 zmap 的键。查不到时 `0x77D236` 走到 `0x77D38C` 的异常路径。已还原。

smap 的值是槽位串，不是序号。`hairOverHead` 的值是 `H1`，`hair` 是 `H2`，`mailArm` 是 `MaGw`，`cap` 是 `CpHdH1H2H3H4H5H6HsHfHbAfAyAsAe`。这些字符串是解释函数用的已知样本，不是新的导出。

两字符槽名排在 `characterEnd` 和坐骑层后面，顺序是：

```text
Sd Tm Sr Wg Ma Ws Pn So Si Wp Gv Ri Cp Ay As Ae Am Af At Fc Hr Hd Bd
```

`characterStart` 在文件前部，`characterEnd` 在槽名之前。因此 `Ma` 的整数大于 `Pn`，`Si` 大于 `Wp`，`Cp` 大于 `Hr`，`Hr` 大于 `Hd`，`Hd` 大于 `Bd`。`Bd` 是整张表的最后一项，整数最小。

## 4. 调用链

```text
动作帧枚举画布                         0x413C6B
  参数：画布节点、物品 vslot、物品 islot
  -> 0x402442  复制两串，分配 0x34 字节的画布对象
       -> 0x77D236  填写 priority、tag、zIndex
            -> 0x77CF86  读 z，查 zmap 与 smap
                 -> 0x77CE9A  两串求交
       zIndex == zmap["face"] 则释放，不入链
       否则按 zIndex 插入链表
帧装配完成后
  -> 0x401DE9
       -> 0x401C74  同一帧的槽位冲突，写可见标志
绘制
  -> 0x401FFE  标志为 0 则跳过该画布
```

`0x402442` 的另外一个调用点是 `0x41436C`，参数形状相同。已还原。

## 5. 画布对象

`0x40394A` 分配 `0x34` 字节，构造函数 `0x4048E9`。虚表最终是 `0xAFE4B4`。`0x402CDA` 做字符串赋值：分配 `0xC` 字节的对象，把指向它的指针放进字段。这个对象的第一个 dword 是宽字符指针，长度在字符数据前 4 字节，单位是字节，宽字符个数要再除以 2。已还原。

`0x77D236` 是 `thiscall`，`ret 0xC`，三个参数：

| 栈 | 含义 |
|---|---|
| arg0 | islot 字符串 |
| arg1 | vslot 字符串 |
| arg2 | 画布的 WZ 节点 |

islot 为空而 vslot 非空时，函数直接抛异常。然后：

| 偏移 | 写入 |
|---|---|
| `+0x10` | islot |
| `+0x0C` | vslot |
| `+0x30` | 画布节点，带 AddRef |
| `+0x18` | islot 各槽在 zmap 中的最大整数。初值 `0x80000001`。临时缓冲固定是 2 个宽字符，每次前进 4 字节 |
| `+0x14` | 先清空，再由 `0x77CF86` 写成 `tag` |
| `+0x24` | `0x77CF86` 的返回值，即 `zmap[z]` |
| `+0x1C`、`+0x20`、`+0x28`、`+0x2C` | 从画布节点读出的四个整数，调用分别是 `0x40C250`、`0x40C2E7`、`0x4100A1`、`0x4100C8`。`0x402442` 把后两个取负后写到外层对象的 `+0x0C`、`+0x10`，和原点的用法一致。这四个整数的属性名这次没有逐个对上 |

`+0x18` 的比较是「已有值小于新读到的整数则替换」，所以留下的是最大的编号，也就是 islot 里最靠前的那个槽。长袍 `MaPn` 的 priority 是 `zmap["Ma"]` 和 `zmap["Pn"]` 里更大的一个。`Ma` 排在 `Pn` 前面，结果是 `zmap["Ma"]`。已还原。

## 6. 读 z 并求交：`0x77CF86`

三个参数。arg0 是画布节点。arg1、arg2 都非空时才查 smap。`0x402442` 传进来的就是 vslot 和 `&画布.+0x14`。

1. 取 zmap 属性。节点没有 `z`，或变体是空的，返回值保持进入函数时的 0。
2. 把 `z` 转成字符串，再按这个名字取 zmap 的子节点，读出整数。这就是返回值，稍后存在画布 `+0x24`。
3. 用同一个 z 名字取 smap 的子节点，并转成宽字符串。转换失败就不写 `tag`，`+0x14` 保持第 5 节里先清掉的空值。
4. 调用 `0x77CE9A(输出, vslot, smap值)`，把结果交回 `+0x14`。

`0x77CE9A` 已还原：

1. 两个长度都按宽字符计。任一长度的最低位是 1，走进 `0x77CF6A` 的异常路径。槽位串必须是偶数个字符。
2. 按较长的那一串分配输出缓冲。
3. 外层扫第一串（vslot），每次 4 字节。内层把第二串（smap 值）重置到开头，同样每次 4 字节。两 dword 相等就把这组两个宽字符追加到输出。
4. 第一串扫完后，把输出交给 `0x77D462`，再赋给调用者给的字符串对象。

所以 `cap` 那一长串不会整串进 `tag`。帽子 `vslot = CpH1H5` 时，`z = cap` 的 `tag` 是 `CpH1H5`：smap 里还有 `Hd`、`H2` 等，但这顶帽子的 vslot 没有它们。`z = hairOverHead` 且头发 `vslot` 含 `H1` 时，`tag` 就是 `H1`。

## 7. 谁挡住谁：`0x401C74`

`this` 是当前帧的动作对象。链表头在 `this+0x10`。每个结点 `+4` 是包装对象；包装对象 `+0x20` 是第 5 节的画布，`+0x14` 是可见标志。画布自己的 `+0x14` 仍是 `tag` 字符串，两个 `+0x14` 不是同一个字段。

函数先看 `this+0x38`。唯一写入在 `0x411524`：`mov [esi+0x38], eax`，`eax` 是 `0x41151C` 对 `call 0x4153FB` 的返回值。调用时 `ecx` 是另一个对象的 `+0x29C`。返回指针的第一个 dword 是宽字符指针，长度在字符缓冲前 4 字节，再右移 1 位得到字符数。长度为 0 或指针为空就跳过。否则按两个宽字符一组，键是 `(第一字 << 16) | 第二字`，调用 `0x4036FA`。插入前把值槽清成 0，`0x4036FA` 把这个 dword 抄进表结点的 `+0xC`。已还原。这串字符从哪份 WZ 来，未闭合。

然后沿链表。表只活在这次调用的栈上。

1. 把当前包装的可见标志设为 1（`0x401D37`）。
2. 取出画布 `tag`。装入时先用空指针调用 `0x402D35`，`+0x14` 被写成空指针；只有求交成功才覆盖。指针为空时，`0x401D52` 仍执行 `mov ax, [edi]`。静态上没有「空 tag 则保持可见并离开」的分支。指向单个 `0` 的空串会立刻结束循环，标志保持 1。未闭合的是缺 smap 的画布在运行里会不会真的带着空指针走进来。
3. 对 `tag` 里的每个槽位做表查找（`0x4036AA`）。命中时把结点 `+0xC` 写回调用方。
   - 没有：把当前包装指针插入这把键，继续下一个槽。
   - 有，且存的值是 0：不读 `+0x18`，当前包装的标志清 0，这张画布剩余槽位不再看。`+0x38` 预置的键走这里，本帧内也不会被画布覆盖。
   - 有，且双方 `画布+0x18` 的差为 0：两张都不改，继续下一个槽。
   - 有，且已有编号减去当前编号大于 0：当前包装的标志清 0，转到链表的下一张。
   - 有，且差小于 0：对方包装的标志清 0，键改记到当前包装，继续当前画布的下一个槽。

差的算法在 `0x401D90`：`已有画布+0x18 - 当前画布+0x18`，`je` 先处理相等，随后的 `jge` 只剩下已有编号更大的情况。编号越大越优先，也就是 zmap 文件里越靠前的 islot 越优先。已还原。

因此：

- 一个槽位输了，整张画布不画，不是只藏这个槽。
- 同一 `islot` 的画布 `+0x18` 相同，相等分支让它们互相留着。
- 两件 `+0x18` 相同的装备同时出现时，这一函数也不让其中一件整张消失。装备栏里不能同时穿上的部位，不由这个函数解决。
- 链表按 z 序号从小到大排，冲突从链表头走，先遇到更靠后的层。先遇到只决定谁先占住空槽。槽一旦有主，仍按 `priority` 决定留谁。绘制先后不代替这个比较。

## 8. 入链和绘制

`0x402442` 在 `0x4024DE` 比较画布 `+0x24` 和 `0xBD8FAC`。相等就释放刚分配的包装，不插入。脸层的画布不进这条链表，也不参加第 7 节。表情另由谁画，这次没有追。已还原的是「这条链不要脸层」。

其余画布按 `+0x24` 插入。已有结点的序号大于新画布时，插在该结点之前，否则继续向后。序号小的在前，序号相同的后插入的在后。靠后的层（更负的编号）在链表头。已还原。

`0x401FDF` 沿同一条链表画。`0x401FFE` 比较包装 `+0x14`，为 0 就跳到 `0x402232` 取下一张。标志非 0 才用 `+0x24` 做后面的分支：

- 某个调用参数非 0 时，拿 `+0x24` 和 `characterStart`、`characterEnd` 比，分别走 `0x402114` 与 `0x40219B`，两边最后都调用虚表 `+0x80`。
- 该参数为 0 时，拿 `+0x24` 和脸层编号比，仍然是两条绘制调用，不是跳过。

`characterStart` / `characterEnd` 在这里选择绘制入口。它们不把标志清 0。已还原到这个程度；两个入口分别画到哪张画布上，未闭合。

## 9. 用已知样本套这条函数

下面用设计文档里已经写过的 `vslot` / `smap` 值演算，用来核对函数，不是新的资源结论。

头发 `islot = Hr`，`vslot = H1H2H3H4H5H6HfHsHb`。`hairOverHead` 的 smap 是 `H1`，所以这张画布的 `tag` 是 `H1`，`priority` 是 `zmap["Hr"]`。普通帽子 `01000000` 的 `vslot` 是 `CpH1H5`，`islot` 是 `Cp`。它的 `z = cap` 时，smap 那一长串和 vslot 的交是 `CpH1H5`。两边都有 `H1`。`Cp` 在 zmap 里排在 `Hr` 前面，帽子的 `priority` 更大，头发这张画布的标志被清掉。主头发 `z = hair` 的 smap 是 `H2`。这顶帽子的 vslot 没有 `H2`，帽子不声明 `H2`，主头发留着。

若帽子的 vslot 含有 `H2`，`z = cap` 的 `tag` 里就会有 `H2`，主头发同样整张被清掉。函数没有「smap 较长就免于比较」的长度判断。

身体 `islot = Bd`，`vslot` 通常只有 `Bd`。`mailArm` 的 smap 是 `MaGw`，交是空的。空 `tag` 不声明任何槽，这张身体画布不会因为第 7 节被清掉。上衣自己的 `mailArm` 画布会声明 `Ma`。两张画布的 z 名相同，z 序号相同，后插入的画在前面。身体袖子是被盖住，不是被这条函数标成不画。

长袍样本 `01050000` 的 `islot` 是 `MaPn`，`priority` 取 `zmap["Ma"]`。普通上衣 `01040000` 的 `islot` 是 `Ma`，`priority` 相同。双方 `tag` 即使都含有 `Ma`，相等分支也不清标志。裤子 `islot` 是 `Pn`，编号小于 `Ma`。长袍某张画布的 `tag` 若含有裤子那张画布也声明的槽，裤子那张整张不画。原先「长袍整件盖住上衣和裤子」里，裤子可以靠编号成立，上衣不靠这条函数隐藏。

双手武器样本 `01422057` 的 `islot` 是 `WpSi`。`Si` 排在 `Wp` 前面，`priority` 是 `zmap["Si"]`，和盾的 `islot = Si` 相同。共享槽位时两张画布都留着。原先「`WpSi` 因此盖住盾」不是 `0x401C74` 的结果。盾还在不在画面上，看两张画布的 z 序号谁更靠前，以及装备栏是否允许同时穿上。

## 10. 和原先四条推断的对应

| 原先的读法 | 函数里实际是 |
|---|---|
| 另一件的覆盖槽含有这件 islot 的任一槽，则整件不画 | 比较的是每张画布的 `tag`，不是整件 islot。输的是这一张画布。优先权是 islot 在 zmap 里的编号，不是「谁的 vslot 写了谁的 islot」 |
| smap 只有一个槽，且被别人的 vslot 含有，则这张画布不画 | 单槽只是交出来的 `tag` 恰好一组。隐藏还要看双方 `priority` |
| smap 长于两个字符时，不因为沾到其中一个槽就藏 | 没有和 2 比较的分支。长 smap 先和本装备 vslot 求交，交出来的每一组都参加占槽。帽子不被头发藏掉，是因为 `Cp` 的编号大于 `Hr` |
| 一件装备不隐藏自己的画布 | 成立。同一 islot 的 `priority` 相等，相等分支不清标志 |
| 长袍 `MaPn` 整件盖住上衣和裤子；双手武器 `WpSi` 整件盖住盾 | 上衣和盾的 `priority` 与这两件相同，相等分支不清标志。裤子的 `priority` 更小，只有双方 `tag` 交到同一个槽时，裤子那张画布才被清掉 |
| 空 smap 不参与遮挡、照常画 | 缺 smap 时 `0x402D35` 把 `tag` 写成空指针。可见标志仍先被写成 1。空指针在 `0x401D52` 被当成字符指针去读，没有单独的通过分支 |

调用方传入的部件数组顺序仍然没有遮挡语义。锚点顺序是摆放用的，绘制顺序是 z 序号链表。

照着下面写，结果与 `0x77CE9A`、`0x77D236`、`0x401C74` 一致。`pairs` 把字符串按两个字符切开。zmap 缺键、或任一字符串的字符数是奇数，装入失败。

```text
priority(islot) = max(zmap[token] for token in pairs(islot))
                  初值 0x80000001
tag(vslot, z)   = [token for token in pairs(vslot) if token in pairs(smap[z])]
                  缺 smap 时不产生 tag
zIndex          = zmap[z]
```

`zIndex` 等于 `zmap["face"]` 的画布不进链表。其余按 `zIndex` 升序插入，相等的排在已有画布后面。

```text
owners = {}
for token in pairs(action.preset):      # this+0x38，来源未闭合
    owners[token] = None                # 表里的值是 0
for canvas in list:                     # 从靠后的层走到靠前的层
    canvas.visible = True
    for token in pairs(canvas.tag):
        if token not in owners:
            owners[token] = canvas
            continue
        prev = owners[token]
        if prev is None or prev.priority > canvas.priority:
            canvas.visible = False
            break
        if prev.priority == canvas.priority:
            continue
        prev.visible = False
        owners[token] = canvas
```

绘制跳过 `visible` 为假的包装。其余按链表顺序画，先画编号更小的层。

## 11. 未闭合

- `this+0x38` 那串预置槽位从哪个 WZ 字段来。值已经确定是 0，效果是无条件占槽；缺的是字符串本身的名字。
- 缺 smap 时 `tag` 字段是空指针，`0x401D52` 会读地址 0。没有在运行里确认这张画布会不会走到冲突函数。
- 脸层被排除之后，表情画布由哪个函数加回链表。
- `0x401FFE` 之后 `characterStart` / `characterEnd` 两个绘制入口各自的目标画布。`0x40200B` 在参数 `[ebp+0x1C]` 非 0 时才进入这组分支，两边最后都调用虚表 `+0x80`。
- 画布 `+0x1C`、`+0x20`、`+0x28`、`+0x2C` 与 `origin`、`map` 各锚点的逐项对应。`origin` 的字符串编号 798 在别的读取点出现过，没有和这四个调用逐一配对。包装对象的 `+0x0C`、`+0x10` 是画布 `+0x28`、`+0x2C` 取负，这一点已还原。
