# M7.6 动态 viewport 重布局与视觉 soak — 验证证据

> **里程碑状态：2026-11-21，M7.6 实验切片已在真实 `230030200`、Subsystem、WebProjector 与 canonical PWA 路径上闭环。**
> **批准状态：组件 ABI、viewport envelope ABI、`+0x98` 视差、type5–7、flow2/3、CMS079 `rx` 像素 parity、正式 FieldPlan ABI 仍未批准。**

## 1. 范围与证据边界

- **PRODUCT-DECISION**：在 `800×600`…`1000×700` 闭包内，viewport 尺寸变化只重算 **12** 条 viewport-bound Back（type1–4 水平重复）与 **11** 条 `flow=1` Obj 的 `data.layout` + host 几何；Camera counter-position、静态 batch、Portal、avatar 与 type0/零步长 Back 不重读 Content、不重发表数据。
- **fail-closed**：`VIEWPORT_RELAYOUT_ENVELOPE` 外任何尺寸由 Subsystem 抛 `RangeError` → `ADVENTURE_VIEWPORT_PROJECTION_FAILED`；与 M7.4 `BACK_LAYOUT_LIMITS` 叠加。
- **不支持（显式缺口）**：`+0x98` 视差、type5–7、flow2/3、envelope 外自适应、完整 0x66A8D5 / `+0x90` 注册语义、CMS079 Obj `rx` 精确 parity。

## 2. 架构与失效边界

- LoomRealm Subsystem 仍是业务权威；`projectViewportRelayoutUpdates` + `projectBackCameraUpdates` / `projectObjFlowCameraUpdates` 仅经 `domain.update` patch attrs/`data.layout`。
- `ms-map-back` / flow `ms-map-object` 将 Content 签名与 layout 签名分离：`layout` 变更走 `_relayoutViewportSurface`，保留 bitmap、scroll/frame 钟；`paintCommits` 增长、`resourceReads` 不变。
- 初次进入或 Portal target 构造也对当前 envelope 内 viewport 应用同一纯投影；800×600 首次进入不会先发布 1000×700 stale layout。envelope 外仍 fail-closed。
- 场景 replace（B↔C）重置 `projectedViewportWidth/Height` 与子节点镜像；`activeRenderChildren` 与 patch 同步，避免退役后 stale relayout。
- renderer 在异步读取完成后重新读取当前 carrier data/attrs 并复验签名；加载中发生 resize 时，旧 box/layout 不得覆盖最新 viewport。relayout 会重启捕获 layout 的 Back/Obj 动画回调，并在写入 Canvas device size 前重复预算检查。
- 浏览器 **UA 堆指标在本机不可用**；Soak 使用 **DOM 节点数 + Canvas 像素/1000** 确定性代理（见 `M7_6_VIEWPORT_BUDGETS.maxHeapDomProxyScore`）。
